# 08 · AI 链路

> 上级：[Wiki 首页](./README.md) · Provider 实现：`web/functions/_shared/workersAi.ts`

---

## 设计原则

1. **AI 全在 Cloudflare**（Workers AI `AI` binding，无 Key / 网关）  
2. **演示不断线** — 远程失败必有本地模板  
3. **人格上下文** — 始终带上 toy 的 role / traits / bio / monologue  
4. **记忆可注入** — 对话带近期 entries 摘要  

---

## 链路 A · 日记分析

```
ComposePage / 重写
  → analyzeEntry()          # web/src/ai/analyzeEntry.ts
    → POST /api/analyze-entry
      → workersAi (env.AI.run)
    → 失败 / 关闭：generateLocalAnalysis()
  → 用户可编辑 title / aiDiary
  → api.createEntry 或 regenerate
```

图片：前端本地完成 OCR / 色调分析，把 `hasPhoto` + `imageToneDescription` 传给 Function
作为氛围参考；图片本身不再上传给模型。

Workers AI 无 `response_format`，Function 从代码围栏 / 正文提取 JSON，
解析失败时再发一次修复请求。

---

## 链路 B · 对话

```
ConversationPage
  → chatToyReply()          # web/src/ai/chatToyReply.ts
    → POST /api/chat
      body: message, toy, history(≤12), memories(≤6), quietMode
    → 失败：localPersonaReply + API 错误气泡 / Toast
  → chatStorage 按 toyId 追加
```

**安静模式**（`toydairy.quietMode`）：更短、少追问；并抑制 `ToyNudgeHost` 主动打扰。

---

## 链路 C · 人设生成

```
NewToyPage
  → generateToyProfile()    # 走对话/分析同类适配或本地
  → 填充 bio + monologue
```

失败用本地性格模板，不阻塞保存。

---

## Provider 适配

AI 由 **Cloudflare Workers AI** 承担（`wrangler.jsonc` 的 `"ai": { "binding": "AI" }`），
Functions 直接 `env.AI.run(model, { messages })`，没有 Key / 网关 / 额外服务器。

| 顺序 | 模型 |
|------|------|
| 1 | `AI_MODEL`（可选） |
| 2 | `@cf/qwen/qwen3-30b-a3b-fp8` |
| 3 | `@cf/meta/llama-3.3-70b-instruct-fp8-fast` |
| 4 | `@cf/meta/llama-3.1-8b-instruct` |

任一模型失败会自动尝试下一个；全部失败时返回 `triedModels` 与 `detail`。
响应解析兼容 `{ response }` 与 `choices[].message.content`，并会剥离 `<think>` 推理块。

排障入口：`GET /api/health` 查看 binding 与当前模型。

## 本地能力（非 LLM 服务端）

| 能力 | 库 | 说明 |
|------|-----|------|
| 抠图 | `@imgly/background-removal` + ONNX | 浏览器内；AGPL；动态 import |
| OCR | tesseract.js | 拍照记一笔填描述 |
| 贴纸 | Canvas 512 白边 | `createStickerAvatar` |

---

## 安全

- AI 不需要 Key，也没有可泄露的上游凭证
- 抠图默认本地，原图不强制上传  
- 演示 CORS `*`；生产应收紧
