## 1. 产品基本信息

| 项 | 内容 |
|----|------|
| **产品名称** | Toy Dairy（玩偶生命手帐） |
| **一句话定位** | 让玩偶拥有身份与视角的 AI 生命手帐 |
| **比赛主题** | **Reverse** — 视角与主客体反转 |
| **主题释义** | 把「人看玩偶」反转成「玩偶看世界」：让陪伴物从被记录的**客体**，变成共同生活的**叙事主体** |
| **Slogan** | Reverse the gaze. 从物品到陪伴。 |
| **产品形态** | 移动端优先 Web App（手帐风 UI，桌面端居中约 390px 手机框） |
| **线上地址** | https://toydiary.pages.dev（Cloudflare Pages 项目 `toydiary`） |
| **目标用户** | 喜欢收藏 / 携带玩偶旅行、拍照，并希望用玩偶记录生活与情绪的年轻人 |
| **核心痛点** | 玩偶在照片里往往只是「物品」——没有身份、独白与可回看的共同故事 |
| **核心价值** | 身份卡（谁）→ 记录（发生了什么）→ 双视角叙事（我怎么说 / 它怎么说）→ 成长时间轴（我们走过哪里） |
| **差异化** | 玩偶是主角，不是滤镜；主人叙述与玩偶第一视角**并列**，不混成一段 AI 文案 |
| **主路径** | 档案 → ＋记一笔 → 成长时间轴 → 双视角详情 →（可选）对话 / 正数日 / 分享 |
| **技术栈** | React + TypeScript + Vite + Tailwind · Cloudflare Pages (+ Functions) |
| **数据策略** | 演示以浏览器 Mock（localStorage）为主；AI 日记 / 对话可走 Pages Function |

### Reverse 如何落在产品里

| reverse 层 | 产品落地 |
|------------|----------|
| **视角反转** | 同一瞬间同时呈现「我的视角」与「玩偶视角」第一人称日记 |
| **主客体反转** | 身份卡赋予名称、生日、性格、独白——玩偶从道具变成角色 |
| **关系反转** | 成长轨迹 / 纪念日沉淀双向记忆，而不只是人单方面收藏 |

### 产品原则

1. **玩偶是主角，不是滤镜** —— 每条记录优先可读「玩偶视角」  
2. **双视角** —— 主人叙述（`userNote`）与玩偶日记（`aiDiary`）并列  
3. **手帐感 > 功能堆叠** —— UI 软、可滑、可点开回味  
4. **演示优先** —— 主路径 3 分钟能讲完；假数据也要像真故事

## 2. 产品背景

越来越多年轻人会带着玩偶旅行、拍照，将玩偶作为情感陪伴与记忆载体。但玩偶在照片里往往只是「物品」。Toy Dairy 用 AI 赋予玩偶人格与第一视角叙事，让它成为旅程中的陪伴者与记录者。

这与比赛主题 **Reverse** 一致：我们做的不是“多一个 AI 写文案的工具”，而是完成一次 **谁在讲故事** 的反转——从「我记录玩偶」到「玩偶与我共同记录生活」。

**核心体验链路：**

```
身份卡 → 上传旅行/日常照片或文字 → 生成主人视角 + 玩偶视角
  → 成长时间轴 / 旅行地图 → 对话陪伴 → 正数日与分享卡片
```

## 4. 核心对象（契约摘要）

**Toy（玩偶）**  
`name, birthDate, birthPlace, role, traits[]` → 派生 `zodiac, bio, monologue, avatarUrl?`

**Entry（事件/日志）**  
`type(travel|daily|memorial|text|heart), date, location?, place?, title?, userNote?, mood?, imageUrl?, aiDiary?, tags?`

| 字段 | 产品含义 |
|------|----------|
| `userNote` | **我的视角**（主人怎么叙述这件事） |
| `aiDiary` | **玩偶的视角**（第一人称 AI/预置日记） |
| `place` | 结构化地点（地图、城市统计） |

**双视角 UI 规则**

1. 我的视角：优先 `userNote` → 否则 `title` → 否则按地点/玩偶生成一句兜底  
2. 玩偶视角：优先 `aiDiary` → 否则按性格模板兜底；「重写」只动玩偶侧

## 5. MVP / 冲刺范围

> 状态：前端 Web 已可演示；数据以浏览器 Mock 为主；真后端 / R2 为加分项。

### 5.1 必须能演示（P0）

| 故事 | 验收标准 |
|------|----------|
| **建玩偶** | 填名称/生日/出生地/身份/性格 → 得到星座+简介+独白 → 身份卡可看（含贴纸头像） |
| **记一条** | 选玩偶 + 图或文字 + 日期/地点 → 保存后出现在成长/档案相关列表 |
| **双视角详情** | 从成长点进事件：上块「我的视角」= `userNote`；下块「玩偶视角」= `aiDiary`；可「重写」 |
| **切换玩偶** | 成长/档案能切换当前玩偶，列表跟切换走 |
| **演示数据** | 种子文案够长、够有画面；可重置 / 导入导出恢复 |

### 5.2 已有则展示，不做深挖（P1）

- 回忆展厅 / 正数日卡片与分享  
- 旅行地图（Leaflet + seed/Nominatim 坐标）  
- AI 对话陪伴 + 应用内 nudge  
- 主题配色、手帐视觉 polish  
- 相机 OCR 填描述  
- 成长轨迹 PNG / JSON 备份  

### 5.3 明确砍掉 / 下轮（Out of scope）

- 硬件激活端作为 Web 硬依赖  
- 完整账号云同步 / 支付会员  
- 插画生成、完整社交平台发布链路  
- 桌面客户端打包  
- 系统级推送 / 正式 iOS 小组件  

**真后端（可选加分，不阻塞演示）**

| 项 | 说明 |
|----|------|
| API | 对齐 plan：`/toys`、`/entries`、generate-profile / regenerate |
| 存储 | D1 存元数据；R2 存图（资源已可预建） |

## 6. 主路径用户流程（演示脚本）

```
打开 App（登录或随便看看）
  → 档案：介绍当前玩偶（Luna）
  → ＋：拍/选一张图或写一句 → AI 生成玩偶日记
  → 保存
  → 成长：时间轴点进刚写的那条
  → 详情：朗读「我的视角」+「玩偶视角」；可选分享卡片
  →（可选）地图轨迹 / 对话闲聊 / 正数日卡片
  → 结束：强调「玩偶有了自己的记忆」
```

时长目标：**≤ 3 分钟**。

## 8. 产品愿景（原文模块，不约束冲刺砍功能）

### 用户使用流程（愿景）

购买玩偶 → 创建玩偶身份 → 生成身份卡 → 上传旅行/日常照片 → AI 结合性格生成第一视角日记 → 成长时间轴 → 纪念日回顾 → 对话与玩偶社区。

### 核心模块（愿景）

1. **玩偶身份卡** — 名称、生日、出生地、星座、性格、人设独白  
2. **旅行生命日志** — 照片 + AI 文案 + 地点  
3. **纪念日 / 回忆展厅** — 陪伴天数、幻灯片、分享卡片  
4. **成长档案** — 天数、城市、轨迹  
5. **互动延伸** — AI 对话；玩偶间动态（社区）  

更细的纪念日实体设计见 [`daysmatter_feature.md`](../daysmatter_feature.md)。  
路演叙事见 [`advx_show.md`](../advx_show.md)。
